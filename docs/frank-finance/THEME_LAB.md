# Theme Lab — the three-axis look system

Frank Finance can be re-skinned end to end from **Settings → Appearance**. Three
independent axes multiply out to 1,000 combinations:

| Axis | Attribute on `<html>` | Options | Owns |
|---|---|---|---|
| Palette | `data-palette` | 10 | color primitives — paper, ink, the neutral ramp, accent hues |
| Typeface | `data-typeface` | 10 | body / display / mono pairing, tracking, numerals |
| Style ("skin") | `data-ui-style` | 10 | shape, depth, density, motion, placement |

Registry (single source of truth for the UI *and* model validation):
[`app/models/ui_theme.rb`](../../app/models/ui_theme.rb).
CSS lives in [`app/assets/tailwind/themes/`](../../app/assets/tailwind/themes/).

## Why this works without touching 200 views

The design system is fully token-driven: every surface, border, shadow and text
color resolves through the neutral ramp (`--color-gray-*`) plus
`--color-white` / `--color-black`, and the alpha ladders compile to runtime
`color-mix()` over those two. So re-pointing ~30 primitives re-skins ~490
`bg-container` usages, 154 card shadows, and all text colors at once.

```
palette  → primitives (--color-white/black, --color-gray-*, hue ramps)
             ↓ (base design system maps aliases onto them)
           --color-surface / --color-container / text-primary / hairlines / shadows
```

## Storage and application

- Columns `users.ui_palette` / `ui_typeface` / `ui_style` (migration
  `20260729220000`), validated against the registry in `User`.
- Server-rendered onto `<html>` in `layouts/shared/_htmldoc.html.erb` so the
  first paint is already themed.
- **Turbo never re-renders `<html>`.** After a Turbo visit the server-rendered
  attributes go stale for the life of the tab, so an in-body element carries the
  values and `look_controller.js` writes them onto `documentElement` on connect.
  This mirrors the pre-existing `theme_controller` two-instance pattern — do not
  "simplify" it away.
- The settings pickers preview instantly (they set the Stimulus values directly)
  and auto-submit to persist. `POST settings/appearance/randomize` samples a
  combination; `reset` returns to the house look.
- `look_controller` dispatches `theme:change`, which chart controllers already
  listen for.

## Palettes

Generated by `scratchpad/gen_palettes.py` (kept in the session scratchpad; the
generated CSS is committed). Each palette defines a tinted neutral ramp built in
OKLCH **at the stock ramp's lightness steps**, so contrast behavior carries over
between looks, with hue shifting from highlights to shadows.

**Contract — this ordering is load-bearing:**

```css
[data-palette="x"]                  { /* LIGHT primitives only */ }
[data-palette="x"][data-theme="dark"] { /* DARK primitives + aliases */ }
```

The light block must never set semantic aliases (`--color-surface`,
`--color-container`, …). The base `[data-theme="dark"]` block maps those onto the
ramp; a light block that also set them would leak light surfaces into dark mode,
because it loads later at equal specificity.

Every palette is contrast-checked at generation time: body text ≥ 4.5:1 on both
container and inset surfaces, accents ≥ 3:1, and gains vs losses must be
distinguishable by luminance or ≥ 60° of hue. Text and link stops are auto-
darkened/lightened (preserving hue and chroma) until they clear AA — which also
lifted the stock Graphite ramp, whose `gray-500` sat at 4.43:1 on inset
surfaces.

## Typefaces

Eleven families, latin-subset variable woff2, **self-hosted** under
`app/assets/fonts/**` (Propshaft resolves the `./dir/file.woff2` logical paths).
Nothing is fetched from a third party — this is a finance app, and `font-src`
stays `:self`. All OFL-1.1; see `app/assets/fonts/OFL-NOTICE.md`.

Each pairing sets `--font-sans`, `--font-display`, `--font-mono`, plus
`--type-scale` (optical size correction) and display tracking/weight. Money and
table cells get `tabular-nums lining-nums`.

## Skins

Full authoring contract is the header comment of
[`themes/styles.css`](../../app/assets/tailwind/themes/styles.css). The
essentials:

1. **Write rules unlayered** (never inside `@layer`). Unlayered declarations beat
   Tailwind's `@layer utilities`, so skins win with no `!important`.
2. **Palette-agnostic and font-agnostic.** Only `var(--color-*)` /
   `var(--font-*)` and `color-mix()` over them — never a hex. Provide a
   `[data-ui-style="x"][data-theme="dark"]` twin wherever you use
   `--color-black` / `--color-white` directionally.
3. **Motion** only inside `@media (prefers-reduced-motion: no-preference)`.
4. **Numbers stay scannable** — no tracking or text-transform on money.

### Traps found the hard way (verified by compiling the real stylesheet)

- `--radius-*` **is** overridable and re-shapes all `rounded-*` utilities — but
  `rounded-full` compiles to `calc(infinity * 1px)`, not a token. Sharp skins
  must flatten specific elements (scope to `button`/`a` so avatars stay round).
- `--shadow-xs…xl` is read at runtime **only** by the custom `shadow-border-*`
  utilities (the 154 card usages). Bare Tailwind `.shadow-xs` bakes its geometry
  at build time; only its color is late-bound. To reshape those, override
  `--tw-shadow` from an unlayered rule.
- `--color-alpha-black-50` / `-white-50` is the 1px hairline inside every
  `shadow-border-*`. Pushing it to full ink turns every card outline structural
  (see `brutal.css`).
- The sidebar **width** is controlled by JS (`app-layout` Stimulus classes).
  Express density through padding/gap/font-size, never `width: !important`.
- `#main` is the scroll container; `leftSidebar` is already `overflow-hidden`.
  Adding `overflow` to either breaks scrolling.

### Charts

`utils/theme_tokens.js` resolves tokens to concrete values at draw time (D3
needs real colors for opacity math) and invalidates its cache when any look
axis changes. `observeLookChanges()` replaces the old `data-theme`-only
MutationObserver. Two controllers previously hardcoded light/dark hex pairs
(`goal_projection_chart`, `sankey_chart`) and ignored palettes entirely — both
now read tokens.

**Deliberately not themed:** category, account-type and institution colors
(`Category::UNCATEGORIZED_COLOR`, `Depository`'s brand hex, …). Those are *data*
— user-assigned or brand-accurate — so a palette must not repaint them. The
donut and sankey therefore keep their own category hues over every look.

## Adding a look

1. Add an `Option` to the relevant constant in `app/models/ui_theme.rb`
   (id, name, blurb, preview `meta`).
2. Palette → add an entry to the generator and re-run it. Typeface → vendor the
   woff2 + add `@font-face` and a pairing block. Skin → new file under
   `themes/styles/` + one `@import` in `styles.css`.
3. Nothing else. Validation, the settings picker, and the randomizer all read
   the registry.

## Verifying

Visual regression is the only real test. Boot a mounted container, build CSS,
then screenshot each look:

```bash
docker compose run --rm -p 3001:3000 -v "$PWD/app:/rails/app" \
  -v "$PWD/config:/rails/config" web bin/rails tailwindcss:build
```

Check per look: text contrast in light *and* dark, focus rings still visible,
the dashboard widget grid, a wide table (Transactions), a modal, and the mobile
breakpoint. `prefers-reduced-motion` should silence all animation.
